# PC 与 ESP32-P4 原型方案

状态：用户提出的候选方案，尚未确定具体开发板、外围器件、模型及接口，需实测。

## 结构

Gemini 2 通过 USB 3 直连 PC；PC 运行 ROS 2 相机驱动、语义建图、人物与情绪相关感知、任务决策、记忆和交互算法。ESP32-P4 通过 USB 或其他已验证链路连接 PC，控制电机驱动器并读取编码器与状态；麦克风、扬声器和显示屏可连接 P4，但其具体器件、通信、驱动和并发能力需验证，也可在原型阶段直接接 PC。

电机需独立驱动器和适当电源，不能由开发板 GPIO 直接驱动。P4 负责本地速度闭环、指令超时停止、看门狗与状态反馈；急停应具备独立于 PC 和普通应用程序的软件控制路径，具体制动及断电方式由底盘设计和风险评估决定。通信恢复后不自动恢复先前运动。原型需成人监管，不能因加入上述机制就认定对儿童安全。

## 云端边界

PC 发起 LLM API 请求不意味着推理在本地：如服务位于家庭外，所提交的文本、记忆或其他内容会离开家庭，即使不持久化也属于传输。当前用户数据本地存储目标与云端推理如何共存仍待明确。推荐默认本地推理或仅发送不含用户数据的通用请求；真实用户数据的任何远程处理须先明确授权、服务条款、数据范围和用途，并防止日志及错误报告泄露。删除姓名不等于匿名化。远程服务器同样位于家庭外。

## 工程要点

- 检查 P4 开发板实际引脚和 USB、音频 codec、功放、屏幕接口、内存、带宽和电源；芯片具有外设不代表特定开发板已接出或同时可用。
- 明确 PC 与 P4 协议、音频流传输和屏幕内容刷新方案；先测并发延迟与掉帧。原型阶段采用 USB 音频设备和 PC 直连屏幕可减少集成工作。
- ROS 2 实体相机适配应检查话题、编码、深度单位、RGB-D 对齐、时间戳、内参和 TF；旧项目当前仅实现仿真相机，不能假设实机开箱即用。
- 网络/API 故障时不等待云端指令维持运动；PC 与控制器通信中断时执行已验证的停止策略。地图、记忆、日志和录音录像的生命周期与权限需明确。
- 先用低速、离地或受控场地测试底盘，再逐步验证感知、交互和完整链路；不得直接用于无人监管的儿童环境。
