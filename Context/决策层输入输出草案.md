# 决策层输入输出草案

状态：讨论稿；字段和具体通信机制待验证。

## 输入

- 用户输入与事件：语音识别文本、触屏操作、照护者指令，附来源、时间及识别可信度；必要时请求澄清。
- 感知状态：环境、机器人与人的位置，动作和交互状态；情绪为有不确定性的估计，允许未知，并附时间、新鲜度和置信度。
- 任务上下文：当前场景、任务目标、活动阶段、上一步动作和剩余步骤。
- 控制与设备反馈：动作执行中、成功、失败、取消或超时，设备和安全状态。
- 本地记忆：按当前任务和权限检索相关经历、偏好与明确的照护者设置，标注来源和更新时间。
- 约束：照护者设置、隐私权限、场景内容规则、可用能力及运行安全约束；物理安全由独立控制机制持续保障。

状态可持续更新；用户输入、任务结果、异常或定时等事件触发一次决策。时间过期、冲突和缺失的信息不能当作确定事实。

## 输出

- 交互动作请求：播放经检查的文字/音频、显示内容、等待回应或询问照护者。
- 机器人技能目标：例如导航到指定位置；通过受约束技能接口提交，携带请求 ID、参数和必要期限，可取消并接收反馈。决策层不直接控制电机。
- 任务状态与流程：更新活动阶段，继续、暂停、结束或请求人工介入。
- 记忆写入候选：提出需保存的必要事实及来源，由独立记忆与数据治理模块按权限、用途和保存规则决定是否写入；模型推断不自动视为事实。
- 对外可见状态：向照护者或界面报告必要的进度、故障或需要确认的事项。

## 边界与例子

安全保护、限速、碰撞响应和急停不能依赖决策层或 LLM，控制层须验证并可拒绝动作，安全机制可随时停止。LLM 仅作为可选决策组件，其输出须经过格式和权限检查；外部 API 会传输请求内容，需遵守既定隐私边界。

示例：儿童选择苹果卡片，系统收到触屏事件、活动阶段和相关历史，决策层请求显示苹果并播放对应提示，随后等待反馈；控制层报告播放结果，系统根据儿童回应调整活动。若响应不明，决策层询问或等待，不推断儿童意图或情绪为确定事实。最终是否写入互动记录由记忆治理规则决定。
