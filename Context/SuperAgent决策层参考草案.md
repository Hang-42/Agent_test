# 参考 DeepSeek Super-agent 的决策层草案

状态：设计建议，非已实现方案。参考 DeepSeek 官方原型 https://github.com/deepseek-ai/dsh-superagent-prototype 及其领域模型 https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/001-domain.md 。原项目面向工程任务，以下为针对家庭机器人的改造，不代表原项目原生具备机器人能力。

## 建议结构

感知、用户请求、控制反馈等来源 → 本地事件过滤（去重、时效、规则）→ 状态监听与路由 → 交互 Agent 执行活动；正在进行的交互相关后续事件可定向交给当前交互，停止和安全事件始终走优先路径。交互 Agent 按权限访问本地记忆，向控制层发起受约束的动作请求，接收反馈；记录候选由记忆模块治理。系统健康监控负责软件故障和恢复，独立物理安全机制负责急停等。

## 概念映射

- Trigger：用户请求、互动状态变化或动作完成等事件，附来源、时间、关联 ID、可信度和有效期。
- Router：状态监听与路由，依据明确请求、规则、上下文、当前活动和权限选择忽略、等待、启动、更新或停止；可选 LLM 研判，规则和安全约束优先。
- Worker：交互 Agent，一个受约束的活动执行实例；后续按需求添加其他技能，不预设必须多 Agent 并发。
- Thread/Ticket：可用会话 ID 和活动任务状态追踪上下文及关联事件，避免把执行状态等同于长期记忆。
- Watchdog：监控进程、通信和动作反馈；不替代独立于 PC 和 LLM 的机器人安全保护。

## 本地优先与首期范围

运行状态、记忆、事件和默认推理留在家庭本地；外部 API 涉及数据出境到家庭外服务，按已讨论的权限与数据边界处理。首期仅实现规则过滤、一个路由、一个交互执行器、可取消任务、本地受控记忆和控制反馈；不实现复杂多 Agent 并发、云端常驻或未验证的长期自主行动。安全事件立即触发底层保护，不能等待事件队列或模型。初期评估触发误报/漏报、互动打扰、延迟、停止和恢复、隐私及任务完成情况。
